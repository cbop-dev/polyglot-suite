## 1. Architectural Role & Objective

The primary requirement of the refactoring is that **all corpus-specific information must live strictly in configuration files**, specifically within `src/lib/config/`. 

No Svelte view, route, or state store may hardcode:
* Names of editions (e.g. *"Kirsopp Lake Greek (1912)"*, *"Cohn-Wendland"*, *"Niese"*).
* Supported languages for a corpus.
* Historical eras or author descriptions.
* Milestone badge labels (`§` vs `M.`).
* Custom feature tabs (e.g. Scripture citations).

This document defines the configuration schema (`corpora.ts`), the canon registry structure (`corpora.data.ts`), and the decoupling of `@polyglot/ancient-languages`.

## 2. Configuration Schema (`src/lib/config/corpora.ts`)

### 2.1 Interface Definitions

```ts
export type TextDirection = 'ltr' | 'rtl';

/**
 * Declares a specific textual witness or translation available within a corpus.
 */
export interface TextVersionConfig {
    id: string;              // Unique DB/version ID (e.g. 'lake_grc', 'yonge_eng', 'af_lat')
    language: string;        // Language code: 'grc', 'eng', 'lat', 'hbo', 'syr'
    title: string;           // Full title (e.g. 'Kirsopp Lake Greek Critical Text (1912)')
    shortTitle: string;      // Short header label (e.g. 'Greek (Lake 1912)')
    direction?: TextDirection; // Defaults to 'ltr'
    isDefaultVisible: boolean; // True if column should display on initial load
    order: number;           // Left-to-right display order
}

/**
 * Declares secondary milestone numbering schemes (e.g. Niese, Mangey).
 */
export interface MilestoneSchemeConfig {
    id: string;              // 'niese', 'mangey', 'stephanus', etc.
    label: string;           // 'Niese Section', 'Mangey Milestone'
    badgePrefix: string;     // '§', 'M.'
    badgeColorClass: string; // Tailwind color classes for pill
}

/**
 * Complete metadata contract for a corpus.
 */
export interface CorpusConfig {
    id: string;              // e.g. 'af', 'philo', 'josephus'
    name: string;            // e.g. 'Apostolic Fathers'
    subtitle: string;        // e.g. 'Early Christian Greek writings (1st–2nd century CE)'
    badge: string;           // Short badge for triggers (e.g. 'AF', 'Philo')
    era: string;             // Historical period (e.g. '1st–2nd c. CE')
    author: string;          // Author or collection designation
    primaryLanguage: string; // 'grc', 'lat', 'hbo', etc.
    availableLanguages: string[]; // ['grc', 'eng', 'lat']
    textVersions: TextVersionConfig[];
    milestoneScheme?: MilestoneSchemeConfig;
    coordinateScheme: 'book_only' | 'division_both';
    features: {
        hasScriptureCitations: boolean;
        hasTextualApparatus: boolean;
        hasAudio: boolean;
    };
    citation: {
        author: string;
        seriesTitle: string;
        defaultYear: string;
        publisher?: string;
    };
}
```

## 4. Works Registry (`src/lib/config/corpora.data.ts` or `corpora.generated.ts`)

Works metadata across all corpora is consolidated into a single standard type `CorpusWork`. This data may be maintained manually in `corpora.data.ts` or emitted automatically by the pipeline into `corpora.generated.ts`:

```ts
export interface CorpusWork {
    corpusId: string;
    code: string;                  // Uppercase code ('1CLE', 'OPIF', 'WAR')
    slug: string;                  // URL-friendly slug ('1-clement', 'opif', 'war')
    orderIndex: number;
    category: string;
    abbrev: string;                // '1 Clem.', 'Opif.', 'War'
    titleEnglish: string;
    titlePrimary: string;          // Greek title
    titleSecondary?: string;       // Latin title
    totalDivisions: number;        // Total books or chapters
    minDivision: number;           // Usually 1 (0 for 1 Clement)
    divisionLabel: 'Book' | 'Chapter';
    sectionsByDivision?: Record<number, number>;
}
```

> [!NOTE]
> **Pipeline-Generated Metadata Support**:  
> To prevent manual transcription errors when new corpora are ingested, the pipeline runner may export `corpora.generated.ts` and `corpora.data.generated.ts` directly from compiled databases (mirroring `apps/polyglot-bible-reader`). ACR configuration files may re-export or enrich these generated artifacts without rigid file-naming restrictions.

## 5. Decoupling `@polyglot/ancient-languages`

### 5.1 Removal of Redundant Work Catalogs
* Delete `ANCIENT_CORPORA_WORKS` from [`packages/ancient-languages/src/citations/ancientCorpora.ts`](file:///home/cbrannan/.gemini/antigravity/worktrees/polyglot-suite/audit_acr_refactoring/packages/ancient-languages/src/citations/ancientCorpora.ts).
* Work metadata belongs exclusively in ACR configuration.

### 5.2 Refactoring `formatAncientCorpusCitation`
Refactor citation formatting helpers to receive the work metadata object as a parameter rather than resolving it from an internal static map:
```ts
export function formatAncientCorpusCitation(params: {
    work: { abbrev: string; divisionLabel: string };
    division: number;
    section?: number | string;
    milestone?: string;
}): string {
    const { work, division, section, milestone } = params;
    if (milestone) return `${work.abbrev} ${milestone}`;
    if (section !== undefined) return `${work.abbrev} ${division}.${section}`;
    return `${work.abbrev} ${division}`;
}
```
This preserves the utility of `@polyglot/ancient-languages` while eliminating data duplication.
