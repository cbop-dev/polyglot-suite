### Step 4: Optimize Polyglot Bible Reader (PBR) Without Truncation
**Files**:
- [`apps/polyglot-bible-reader/src/lib/services/dbClient.ts`](file:///home/cbrannan/dev/2-tmp/polyglot-suite/apps/polyglot-bible-reader/src/lib/services/dbClient.ts)

1. **Preserve 100% Full Reference Searches**:
   Do **NOT** impose an arbitrary `LIMIT 250` on `getConcordance`. Unlike Philo/AF/JR, PBR's `concordance_refs` does *not* join `text_units` or load `tokens_json`—it only fetches `(ref_label, work_unit_id)`. For words with hundreds or a couple thousand occurrences (e.g. "θεός", "λόγος", "κύριος"), loading the full reference set is essential so that users can filter by inflection and search across all biblical books (Prophets, Gospels, Epistles) without losing later books.

2. **Fix `getLemmaTotalCount` Fallback (Eliminate Unbounded Range Scans for Counts)**:
   In `dbClient.ts:999-1003`:
   When `lemma_stats` misses or key formatting differs, it currently calls `getConcordance(corpusId, lemma, 0, strongs)` to count rows in JavaScript. Replace this with an instant SQL count:
   ```sql
   SELECT count(*) as cnt
   FROM concordance_refs
   WHERE corpus_id = ? AND (lemma_key = ? OR lemma_key = ?);
   ```

3. **Fix `getWordFrequencyByBook` Fallback (Eliminate Unbounded Client-Side Aggregation)**:
   In `dbClient.ts:1094-1100`:
   If `lemma_stats` lacks precomputed book frequencies, do **NOT** download all 25,000 occurrences to build a `Map` in JavaScript. Replace with an efficient SQL aggregation:
   ```sql
   SELECT substr(ref_label, 1, instr(ref_label, ' ') - 1) as book, count(*) as cnt
   FROM concordance_refs
   WHERE corpus_id = ? AND (lemma_key = ? OR lemma_key = ?)
   GROUP BY book
   ORDER BY cnt DESC;
   ```
